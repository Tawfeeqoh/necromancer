# Necromancer — Demonstration Script

## 1. Demo objective
Show that Necromancer is a tool that resurrects an abandoned legacy application. The application is the patient; Necromancer is the system performing the investigation, repair, and verification.

The demo should prove a complete workflow, not merely show a dashboard.

## 2. Target duration
Aim for 2 minutes 30 seconds or less if the hackathon requires a video under three minutes. Rehearse and time the final recording.

## 3. Demo setup
Prepare:
- Deployed Necromancer URL.
- Controlled legacy PHP/MySQL ZIP.
- Known expected behavior and seeded defects.
- Stable test environment.
- Pre-generated backup artifacts in case a service fails.
- Clean browser session and readable screen resolution.

## 4. Storyboard

### Act 1 — The abandoned application
Show the legacy project and explain:
- It has outdated dependencies.
- Its documentation is incomplete.
- A core flow is broken.
- Its business logic is poorly understood.

### Act 2 — Necromancer investigates
Upload the ZIP.
Show actual:
- Archive validation.
- Codebase Anatomy Report.
- Detected framework/dependencies.
- Evidence-backed intent reconstruction.
- Diagnosis with verified/inferred/unknown labels.

### Act 3 — Controlled revival
Show the staged plan.
Select one repair.
Show the generated diff.
Approve the exact patch.
Show the patch applied to the isolated workspace.

### Act 4 — Guardian verifies
Run tests.
Introduce or demonstrate a known regression case.
Show Guardian blocking it and explaining why.
Then show a safe repair/test result.

### Act 5 — Proof
Show:
- Revived application running.
- Actual test results.
- Revival dossier.
- Original/revived SHA-256 values and integrity verification.

## 5. Suggested closing statement
“Necromancer is an AI-powered software archaeology and resurrection platform. It recovers intent, repairs legacy software safely, verifies behavior, and gives revived codebases a traceable new life.”

## 6. Presentation rules
- Do not claim universal language support.
- Do not call an inferred business rule verified.
- Do not claim security certification.
- Do not claim tests passed unless they ran.
- Distinguish live functionality from fixtures or prerecorded fallback.
- Do not imply that blockchain anchoring exists unless it is implemented and verifiable.
- Ensure the video shows the actual working application on its intended device.
